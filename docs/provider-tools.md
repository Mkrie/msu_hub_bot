# Document, lookup and image tools

`/pdf`, `/topdf`, `/to_pdf` and automatic document previews use PDF24's [conversion tool](https://tools.pdf24.org/en/convert-to-pdf). The adapter selects an available worker from the site's current manifest, uploads once, polls the job and downloads the finished PDF within the same session. Worker hosts are restricted to PDF24; redirects, oversized bodies, unsuccessful jobs and non-PDF downloads are rejected. One conversion has a 180-second deadline, 20 MiB input and 50 MiB output limits. The public website protocol can change independently of the bot.

Plain text is escaped into UTF-8 HTML before conversion so Cyrillic survives the service's plain-text font limitation. UTF-8, BOM-marked UTF-16 and Windows-1251 are supported. Text never becomes active markup. Office documents and images preserve their original format for conversion. Documents go to PDF24; its [privacy policy](https://tools.pdf24.org/en/privacy-policy) governs remote processing and deletion. Returned files are uploaded to Telegram directly rather than exposing provider job URLs.

`/ddg`, `/wiki`, `/вики` and `/duckduckgo` retain DuckDuckGo instant answers and redirects where available. Empty or unavailable instant answers fall back to the [Wikipedia Action API](https://www.mediawiki.org/wiki/API:Action_API), with Russian selected for Cyrillic queries and English otherwise. Replies retain the source link. If both services fail, the encoded search link remains available. The requests use an identifying User-Agent, bounded response bodies and a shared 25-second deadline.

`/bg` runs U²-NetP locally and returns a transparent PNG. Photos stay on the bot's server. Input admission uses the shared media executor; the worker accepts at most 20 MiB/16 MP/8192 pixels per side and reduces the output's longest side to 2048 pixels. Inference uses one CPU thread, a 45-second process deadline and a 1 GiB Linux address-space limit. Existing transparency is preserved. Fine hair, shadows and foreground/background ambiguity can still produce imperfect edges.

The Docker build explicitly downloads the fixed, checksum-verified model into the installed package. For local development, run `uv run python -m msu_hub_bot.media.background_model fetch` after installing dependencies. Inference never downloads models, accepts model URLs or falls back to cloud processing. The model source, checksum and license are recorded in [background_model.py](../src/msu_hub_bot/media/background_model.py) and [third-party notices](../THIRD_PARTY_NOTICES.md). The offline Docker smoke check verifies a real foreground/background mask.

`/i` and `/imgur` use Imgur's official upload API and the configured `HUB_IMGUR_AUTHORIZATION` header (`Client-ID …` or an authorized bearer token). A failed upload is reported without returning provider bodies. Polling has a finite deadline; a configured key or reachable website alone does not establish that uploads are permitted or working. Validate upload permissions with a synthetic image before treating a new hosting configuration as operational.

VK post links and `/vk_post` use the API version pinned in [the adapter](../src/msu_hub_bot/providers/vk/api.py), with a small [Pydantic model subset](../src/msu_hub_bot/providers/vk/models.py) based on the [official schema](https://github.com/VKCOM/vk-api-schema). Unknown fields are ignored; malformed posts are skipped, and unsupported attachments retain a link to the original. Privileged-token access is never sufficient for publication: the outer wall and copied source walls must report themselves open. Deleted, archived, paid, friends-only and private-key posts are excluded; access keys on public attachments do not make a post private. Privacy metadata is checked afresh for each operation rather than cached across requests.

Wall reads are capped at 100 posts and 30 seconds; individual requests have a 15-second deadline, 4 MiB response limit and at most three attempts for VK rate-limit errors. Error bodies and echoed request parameters are discarded. Rendering escapes labels and URLs once, chooses a Telegram-compatible photo size and sends at most ten media items. Long posts retain their full text in reply-linked messages: chunks preserve anchors and respect Telegram's parsed-text, raw HTML and link-count limits. The preview appears once on the last chunk, followed by media once; complete short posts can use album captions. Automatic repost publication remains disabled; the [community interface](community-tools.md) manages paused targets and read-only previews.

Public posts, copies, photos, videos and clips retain their attachment handling, including video playlists and attached communities. Copied bodies, original links and authorship are shown for up to ten distinct entries across two levels; deeper or larger histories retain the outer source link. Public location metadata supports coordinate strings, coordinate objects and named places, with validated map links; an explicit hidden-map flag keeps only the place label. Scheduling, suggestions, ad-only records and unknown post formats remain excluded. Unsupported attachment formats, including `photos_list`, link back to VK instead of silently disappearing.

## Native X posts

Public `x.com` and `twitter.com` status links use [FxEmbed's v2 API](https://docs.fxembed.com/) without credentials. The [adapter](../src/msu_hub_bot/providers/fxembed.py) preserves full text, ordered media, quoted authorship, polls, community notes and available article content. Private/deleted sources are not expanded. Quotes that cannot be loaded remain visibly unavailable; an article excerpt is labelled as an excerpt. Poll results are a snapshot, with voting left in X.

The [renderer](../src/msu_hub_bot/telegram/x_posts.py) sends [Telegram Rich Messages](https://core.telegram.org/bots/api#sendrichmessage): author → full text → gallery → quote. The header starts with a custom logo emoji, followed by the unlinked display name, linked X username and a `↗` link to the post; a blank line separates it from the body. Rich blocks carry explicit links so X usernames do not become Telegram mentions. A media facet disappears from the text only when its matching attachment is displayed. Text is split into reply-linked messages only when rich-message limits require it.

Uploads use validated X CDN URLs, bounded time/bytes and temporary files. Videos carry the selected variant's dimensions when available, otherwise the source dimensions, preserving aspect ratio within Telegram's limits. Unavailable media retains an original link. A definite custom-emoji rejection retries once with the ordinary fallback emoji; definite rich-format/media rejection falls back to complete plain text. Uncertain Telegram writes are never retried.

`auto_x_previews` is independent of `auto_video_links` in chat settings and the Mini App. An absent X preference inherits the stored video preference. Automatic expansion respects commands, active conversations and explicit preview suppression, retains the trigger message, and replies in its forum topic. At most two distinct post links are considered per message. Existing FixupX/FxTwitter embeds are left alone. X and FxEmbed domains never fall through to automatic yt-dlp extraction, including media selectors and unsupported routes; explicit download commands remain available.

Reply-based tools read rich text and nested media through [shared extraction](../src/msu_hub_bot/telegram/rich_input.py). Rich authorship, source links and quoted commands do not trigger automatic handlers. Telemetry records safe operation/provider/outcome fields and Telegram identifiers, never source URLs, post bodies or response payloads.
